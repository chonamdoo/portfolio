# aitrading

Bybit USDT-perp 코인 선물 자동매매 봇.

**코드** 비공개 — 실거래 전략과 거래소 키를 포함합니다
**규모** Python 300파일 53,226줄 · 테스트 함수 1,215개 · 커밋 428
**설계 기록** ADR 17건
**운영** Docker + GHCR, 도쿄 리전 서버에서 가동 중

---

## 무엇을 하는가

차트 패턴(W / M / Head&Shoulders)을 1H·4H·1D·1W에서 탐지하고, CCI 다이버전스와
15분봉 retest를 트리거로 진입합니다.

돈이 실제로 나가는 프로그램이라 "동작한다"의 기준이 다릅니다. 잘못된 진입 하나가
손실로 직결되고, 배포 중 프로세스가 죽으면 포지션이 방치됩니다. 그래서 이 프로젝트의
설계 결정 대부분은 **기능 추가가 아니라 사고 방지**에 관한 것입니다.

## 아키텍처

Clean Architecture 4계층 + 수동 DI (ADR-0007).

| 계층 | 파일 수 | 역할 |
|---|---|---|
| `domain` | 113 | 패턴 탐지, 포지션 사이징, 거래 규칙 |
| `application` | 63 | UseCase (클래스로 구현 — ADR-0013) |
| `infrastructure` | 71 | 거래소 어댑터, DB, 알림 |
| `interface` | 50 | CLI, 워커 진입점 |

Repository 패턴은 5개 애그리거트에 적용했고(ADR-0011), Unit of Work는 명시적 커밋으로
설계했습니다(ADR-0012).

주목할 것은 ADR-0010입니다 — **Repository/UoW 도입을 D11까지 미룬다**는 결정입니다.
필요해지기 전에 추상화를 넣지 않기로 하고, 그 판단 근거와 도입 시점을 미리 기록해
두었습니다. 나중에 ADR-0011, 0012로 실제 도입했습니다.

## 사고를 막기 위한 설계 결정들

**패턴은 셋업과 함께 죽는다** (ADR-0001)
탐지된 패턴이 무기한 살아 있으면 조건이 무너진 뒤에도 진입합니다. 패턴의 수명을
셋업에 묶었습니다.

**백테스트와 페이퍼 엔진을 하나로** (ADR-0002)
두 엔진이 따로 있으면 백테스트에서 통과한 전략이 페이퍼에서 다르게 동작합니다.
같은 코드가 데이터 소스만 바꿔 돌도록 통합했습니다.

**리서치는 페이퍼·실거래를 건드릴 수 없다** (ADR-0014, ADR-0015)
자기진화형 리서치 워커가 운영 중인 전략 상태를 변경하지 못하도록 **데이터베이스를
분리**하고 배치로만 돌립니다. 리서치 결과가 페이퍼에 반영되는 경로는 별도의 명시적
활성화 단계를 거칩니다(ADR-0016).

**거래소는 하나, IP 화이트리스트** (ADR-0006)
멀티 거래소 지원을 의도적으로 포기하고 Bybit 단일 + IP 화이트리스트로 공격 표면을
줄였습니다.

**자동 배포를 두지 않는다** (ADR-0009)
GHCR에서 이미지를 받아 SSH로 수동 배포합니다. CI가 자동으로 배포하지 않습니다.
**진행 중인 OPEN 포지션이 있으면 배포를 보류합니다.** 편의보다 포지션 안전을
택한 결정입니다.

## 품질 게이트

CI(`ci.yml`)가 통과해야 이미지가 빌드됩니다.

```
ruff check          린트
ruff format --check 포맷
mypy strict         타입 (strict 모드)
vulture             죽은 코드 (min-confidence 80)
radon cc -nc        순환 복잡도 (grade C 이상이면 실패)
pytest              커버리지 80% 이상
```

`mypy strict`와 `radon` grade C 컷은 AI가 생성한 코드에 특히 유효했습니다.
동작은 하지만 분기가 과하게 늘어난 함수, 타입이 느슨하게 열린 인터페이스가
사람 리뷰보다 먼저 걸립니다.

테스트 함수 1,215개는 [agent-flow](agent-flow.md)의 `red → green → refactor` 게이트를
거쳐 쌓인 것입니다. red 단계에서 테스트를 실제로 실행했는지는 훅 로그로 검증되므로,
"테스트를 작성했다"는 보고만으로는 다음 단계로 넘어갈 수 없습니다.

## 단계적 운영

기능을 다 만들고 켜는 방식이 아니라, 자본을 단계적으로 노출하는 로드맵을 먼저
정하고 시작했습니다.

| Phase | 기간 | 내용 |
|---|---|---|
| 0 | 3주 | 코드·인프라 셋업 |
| 1 | 2주 | 백테스트 5년 + walk-forward |
| 2 | 6.5주 | 페이퍼 30일 + OOS 14일 |
| 3 | — | 실거래 (자본 5%부터 점진 증액) |

---

## 왜 코드를 공개하지 않는가

실거래 전략 로직과 거래소 연동 설정이 들어 있습니다. 전략은 공개되는 순간 가치가
사라지고, 인프라 설정은 공격 표면이 됩니다.

면접에서 코드 확인이 필요하면 화면 공유로 함께 보는 것은 가능합니다.
